# ADR 0001 · 用 Provider 抽象隔离外部平台

**状态**：已采纳　**日期**：2026-08

## 背景

V1 运行在特定厂商的 Agent Runtime 上，业务代码直接调用该平台的私有工具名
（待办、闹钟），并把某家云市场商品的地址、鉴权头、字段名写死在取数逻辑里。
换环境即完全不可用，也无法开源。

## 决策

引入 `FlightProvider` / `ReminderProvider` 两个抽象基类，作为 Core 与外部世界
**唯一的接缝**。所有具体实现（mock / http / console / ics / json / mcp）都在接口之下。

配套决定：

1. 航班 HTTP 接入**配置驱动**——endpoint / 参数名 / 日期格式 / 鉴权方式 /
   响应路径 / 字段映射全部写在 JSON 里，换供应商不改代码；
2. 默认 Provider 为 **mock**，保证无 Key 可运行；
3. MCP 退化为众多实现之一，工具名与字段映射均可配置，Core 不再依赖任何具体工具名。

## 后果

正面：平台无关、可开源、可 CI、可离线演示；换数据源成本降到写一份配置。

负面 / 待办：Provider 之间的语义一致性需要 **Contract Test** 保证
（例如 `transfer_num` 的含义、价格币种），目前尚未建立。
自动字段探测在生产环境有「猜错但仍能运行」的风险，已提供
`TRAVELWISE_STRICT_FIELDS=1` 强制显式映射作为缓解。
