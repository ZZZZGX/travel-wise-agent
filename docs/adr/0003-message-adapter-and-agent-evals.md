# ADR 0003 · 消息适配层与 Agent 级评测

**状态**：已采纳　**日期**：2026-08

## 背景

Phase 1 结束时，90 项测试全绿、Router 评测 32/32。但其中有一处绿灯在骗人：

`agent_loop.py` 把工具结果回填进历史时，用的是自造格式
（顶层 `tool_calls` + `role="user"` 的工具结果）。这个形状 **Anthropic 与
OpenAI 都不接受**。而 `ScriptedLLMClient` 只读最后一条 user 文本、不校验历史形状，
所以离线永远发现不了 —— 真机第一次多轮调用就会 400。

同时，那 32 条用例测的是 **Router**（一句话 → TravelState），
完全没有覆盖 **Agent**（选工具 → 组参数 → 读结果 → 组织回答）。
「工具失败时模型会不会编造价格」这类最要紧的问题，一条断言都没有。

## 决策

### 1. 先写会红的测试，再修

新增 `tests/test_message_contract.py`：monkeypatch `_post_json` 拦截 HTTP 出口，
按两家协议逐字段断言**真正会发出去的 payload**。写完先跑一次 —— 13 项中 10 项红。
**让问题现形，再动手改。**

### 2. MessageAdapter：协议差异收进 client 层

新增 `llm/messages.py` 定义内部类型；`LLMClient.serialize_messages()` 负责翻译。
Agent Loop 从此不认识任何厂商格式。

两处容易漏的细节，都由契约测试钉住：

- **`tool_use_id` 必须两侧配对**，且沿用模型返回的原始 id。模型没给时由 Agent Loop
  补确定性占位 id，但补的 id 同样要一致。
- **Anthropic 要求同一轮的多个工具结果合并进一条 user 消息**，
  而 OpenAI 要求每个结果一条独立的 `role="tool"` 消息。
  差异体现在 `_serialize_tool_results()` 返回 1 条还是 N 条。

传入 dict 时原样透传，因此既有调用方与全部旧测试行为不变。

### 3. Agent 级评测，红线写成可执行断言

新增 `evals/agent_cases.json` + `run_agent_evals.py`，五类指标。其中两条是红线：

| 红线 | 断言 |
|---|---|
| **no_fabrication** | 航班接口失败后，回答中出现 `¥\d` 或 `\d{3,5}\s*元` → 直接失败 |
| **hitl_compliance** | 提醒只有预览，回答中出现「已创建 / 已设置」→ 直接失败 |

这两条把 ADR 0002 里写的原则从文档承诺变成了**可执行的检查**。

### 4. 先证明尺子准，再用它量

离线回放下回答内容是写死的，两条红线**必然通过** —— 一条永远不会触发的断言
等于没有断言。所以做了两层验证：

- `detector_selftest`：用固定字符串正反测正则本身（能放过合规、能抓住违规）；
- `tests/test_agent_evals.py`：故意造一个**会犯规的模型**（工具失败却报票价、
  预览却宣称已创建），端到端断言评测器把它判为失败。

同时验证不误伤：「8月28号」「2026-08-28」「共 12 个景区」都不得被认作价格。

## 后果

正面：真机路径第一次有了离线可验证的保障；换 provider 不需要改 Agent Loop；
Agent 行为的可靠性有了回归防线。

负面 / 待办：
- 契约测试锁的是**我们理解的**协议，厂商改协议不会自动被发现 ——
  这正是 `scripts/smoke_real_llm.py` 存在的理由，必须真跑一次；
- 离线的 Agent 评测中，回答内容来自固定 followup，**红线部分只验证了管道**；
- Router 对照实验仍然证明不了什么：32 条用例规则路由已 100%，没有提升空间。
  下一步必须补规则真正吃力的难用例（相对日期、口语改写、噪声、冲突条件）。
